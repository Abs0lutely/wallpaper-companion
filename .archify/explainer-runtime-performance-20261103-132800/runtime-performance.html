Wallpaper Companion 性能重构

长图

答

结论

整合版保留原有界面和自动更新，五轮初始托盘内存减少约 44%。功能回归与本轮长时间稳定性复核通过。

  1. 五轮托盘启动中位数从 3896 ms 降到 2010 ms。1
  2. 1000 文件直接发现从 617 ms 降到 26 ms。1
  3. 177 项单元测试和 30 个原生界面流程通过。2

适用于本机 Windows 源码实测；合成资源；WE 与更新服务模拟

1

内存减少了多少？

托盘减少比例为：(118.6 - 66.5) / 118.6 = 43.9%。私有内存不等于工作集或显存。1

首次访问也计入成本

首次创建两个资源库页面约需 257 ms。页面按需创建让启动更轻，但首次访问仍要等待。 用户选择低常驻内存。托盘首次开窗中位数为 2.39 秒，五轮范围 2.13–3.08 秒；基线中位数为 0.87 秒。 后续热重开中位数约 64 ms。开窗计时覆盖调用及 Qt 事件处理，不测屏幕最终呈现时刻。

3

内部怎样减少重复工作？

图的结构
  • 运行状态 runtime
  • 按需页面 pages
  • 资源快照 index
  • 播放与规则 player
  • 有界任务 jobs
  • runtime → pages · 打开时创建
  • runtime → player · 独立运行
  • player → index · 复用候选
  • pages → jobs · 提交任务
  • jobs → pages · 有效结果

隐藏页面停止装饰刷新，播放、规则与壁纸跟随继续运行。目录变更使索引失效，后台重新扫描。切换配置后忽略过期回调。
