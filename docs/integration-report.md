# 性能与自动更新整合记录

本地整合分支：`integration/runtime-auto-update`。工作区：`wallpaper-companion-integrated`。

保留性能分支历史（父提交 `6ab9bba`）并合并已完成的自动更新主线 `ea5bbe93aa1efa5de2f0ecd60dd2c5db66e8f165`。未切换或写入另一个聊天的 worktree，未推送、发布或替换个人版。

## 整合行为

- 更新控制器与延迟创建的设置页解耦，后台检查和状态记录不创建编辑器；首次打开设置恢复最新状态。
- 托盘下载完成提示、安装确认、保存与退出清理保留；没有打开编辑器时不访问未创建的自动保存对象。
- 自动保存与撤销保留更新开关，恢复失败后同步调度器。
- 修复新工作区长路径暴露的 Windows `\\?\` 前缀比较问题；仍先解析真实路径，再按组件验证更新根目录、包所在目录与安装目标。增加前缀等价、拒绝兄弟目录及 `..` 逃逸测试。

## 验证

**177 项单元测试、30 个原生界面流程通过**。双语自动更新流程覆盖模拟下载、校验、取消、安装交接、保存失败回退、退出以及失败安装的恢复/修复。补充实际 API 状态操作在两个长任务占用时仍能完成的测试。

标准审查与整合规格审查通过；新增长路径修复经独立只读复核，目录边界没有放宽。截图复核确认资源列表保持原主题。

测试使用独立 Conda、Store 和临时文件；自动更新使用模拟服务，真实安装交接由 mock 拦截。没有在本轮构建或安装发行包，因此不把另一聊天的云端包验证作为当前整合版的发行验证。

## 五轮性能复核

整合版托盘启动中位数 **2217 ms**，初始私有内存 **66.6 MiB**。

1000 文件场景可见启动中位数 **5146 ms**，初始私有内存 **120.2 MiB**。可见启动与原基线接近，不能将性能专用分支的全部启动降幅直接套用到新增自动更新后的整合版；目录扫描、列表和托盘仍保留主要收益。

自动检查在基准中被 mock，以上不包括联网下载耗时。原始轮次、源码哈希与基准脚本哈希位于 `output/performance/integrated-*`；功能日志与隔离审计位于 `output/ui-validation`，汇总为 `output/verification-final.json`。

性能专用分支的完整前后对比另见相邻 `wallpaper-companion-perf/docs/performance-report.md`。

## 本地使用

双击当前目录 `start.cmd`，或在当前目录执行 `.conda/python.exe main.py`。当前工作区的环境和配置与个人安装版分离。项目版本沿用已合入主线的 0.12.0；这份源码尚未发布为新的二进制版本。
