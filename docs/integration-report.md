- 更新控制器与延迟创建的设置页解耦，后台检查和状态记录不创建编辑器；首次打开设置恢复最新状态。
- 托盘下载完成提示、安装确认、保存与退出清理保留；没有打开编辑器时不访问未创建的自动保存对象。

## 五轮性能复核

最终整合提交 `9c3977e3bf114b55ddc8b7a5e386037854918371` 的托盘启动中位数 **2010 ms**，初始私有内存 **66.5 MiB**。固定基线分别为 3896 ms、118.6 MiB，实测减少约 48.4%、43.9%。

1000 文件场景可见启动中位数 **4564 ms**，初始私有内存 **119.9 MiB**；固定基线为 5084 ms、130.4 MiB。五轮整合版启动范围 4328–4830 ms，基线为 5034–5221 ms。没有进行操作系统冷缓存控制，结论仅代表本机这些新进程轮次。

| 1000 资源操作 | 基线 ms | 最终整合版 ms |
|---|---:|---:|
| 直接文件发现 | 617.18 | 25.58 |
| 播放候选索引读取 | 602.77 | 0.09 |
| 音频列表填充 | 56.09 | 1.92 |
| 壁纸列表填充 | 71.15 | 9.11 |
| 音频搜索 | 15.34 | 4.00 |
| 壁纸搜索 | 5.41 | 5.24 |
| 静音 WAV 进入播放状态 | 17.38 | 17.26 |
| 长任务占用时短查询等待 | 156.27 | 0.20 |

首次创建两个资源库页面需要 **257 ms**，明确计入首次操作成本。播放状态和壁纸搜索的微小差异不作为改善结论。

## 托盘开窗的已确认取舍

用户查看实测后明确选择低常驻内存，不预热字体。真实托盘恢复入口的五轮首次开窗中位数 **2.39 秒**，范围 **2.13–3.08 秒**；基线中位数 **0.87 秒**。这项明显退化是明确接受的取舍，不能用启动提速掩盖。

同组每个进程再开窗五次，热重开中位数为 **63.6 ms**，基线 **82.0 ms**；编辑器不重复创建。计时覆盖显示调用和一次 Qt 事件处理，不测量屏幕合成器最终呈现时刻。

同组启动加首次开窗合计中位数为 **4934 ms**，基线 **5254 ms**。合计按各轮相加后取中位数，不能直接相加两列中位数。该组开窗前私有内存约 **66.9 MiB**。

字体预热探针的首次开窗约 1.16 秒，但私有内存升至 100.7 MiB，故未采用。原始数据位于 `output/performance/integrated-tray-access`；基线在性能工作区 `output/baseline-source/output/performance/baseline-tray-access`。

## 长时间运行与测量范围

落盘采样的三十分钟配置交替/刷新已完成约 900 次。整合版后两个五分钟窗口私有内存为 132.63 → 133.63 MiB，基线为 152.88 → 153.88 MiB，双方仍增加约 1 MiB。分配追踪发现 Mock 调用历史不断保留，当前测量脚本已改用无历史的普通模拟函数；尚未完成修正后的长测，因此**不宣称内存稳定或全部验收通过**。

最终整合提交的十分钟托盘常驻：第 60–120 秒私有内存中位数 66.8 MiB，末一分钟 68.1 MiB，增加 1.3 MiB；同口径基线增加 1.4 MiB。采样器保留数据且真实 Qt 解码器在随机播放时按需初始化，不能将这组数字解释为零增长或绝对无泄漏。

自动检查在基准中被 mock，以上不包括联网下载耗时。原始轮次、源码哈希与基准脚本哈希位于 `output/performance/integrated-final-*`；功能日志与隔离审计位于 `output/ui-validation`，汇总为 `output/verification-final.json`。

独立环境清单位于 `output/performance/environment.json`；两个工作区的 30 项包版本逐项一致。测试启动不包含真实输入钩子和单实例锁初始化，事件处理就绪作为可交互代理指标。

性能专用分支的完整前后对比另见相邻 `wallpaper-companion-perf/docs/performance-report.md`。

## 本地使用

双击当前目录 `start.cmd`，或在当前目录执行 `.conda/python.exe main.py`。当前工作区的环境和配置与个人安装版分离。项目版本沿用已合入主线的 0.12.0；这份源码尚未发布为新的二进制版本。
